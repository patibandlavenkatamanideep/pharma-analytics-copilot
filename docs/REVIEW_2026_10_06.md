## Preserved contracts and limits

Source schema, metric semantics, RLS, WAC restrictions, server-side identity,
typed model plans, deterministic SQL compilation, LangGraph, scoped memory,
OIDC browser binding and ingestion publication remain the governing contracts.
Clarification only resolves bounded ambiguities; it never approves permissions.
Entity resolution selects scoped IDs; request idempotency replays one committed
outcome; ingestion deduplication uses source/event/version/digest; cohort
completeness tracks the entire selected population. These are separate mechanisms.

The audit policy remains **best effort**. `OBSERVABILITY.md` and
`READINESS_2026_10_05.md` specify the stronger alternatives: atomically commit
answer/run/audit before release, or a fail-closed audit write with replay checks.
Both require a product decision about availability and uncertain commit handling.
A process killed after transport but before accounting persists can still leave
unknown spend; the provider invoice is the reconciliation source. The documented
UTF-8/NFKC input bound is still an assumption, not a provider guarantee.

Charts already cover supported time/ranking/group comparisons from authorized
returned rows, with metric/unit/period/snapshot freshness, missing values and an
accessible table. Unsupported multi-grain and scalar shapes keep the table or
headline. No chart fetch path was introduced. Component tests and local browser
journeys do not establish a hosted integration.

`OPERATIONS_DASHBOARD.md` specifies latency, outcomes, usage, admission-pressure,
clarification/repair, freshness and audit-loss panels/alerts. Source labels now
use an operator inventory capped at 64; model labels use the configured model.
Unknown counters aggregate as `other`; unconfigured freshness sources stay absent
rather than merging their ages. Alerts require real backend wiring and agreed
thresholds. WAC revocation staging now starts with an Exec with initial access.
The runbook documents SSO disable and requires security-reviewed rollback images.

A second session had corrected the same 2 October findings independently on

chose this branch as the release line. The two were compared by running each

- What this branch has that the other lacked: the checkpoint-loading fix,

  on Node 20 and on the public GPG fingerprint.

Ported here, each in its own commit: the evidence recorder's count fix
(`cb8f00b`), registration of four log calls plus a registry check
(`7526e69`), the 14 behavioural tests (`a85c91b`; on `58b3d3e` 12 fail and 2
pass, `r5-port-reproduced.json`), and the freshness pool in the connection
budget (`7950e71`).

Behavioural differences between the two implementations, left as they are
here and stated so they can be decided rather than discovered:

- **A number the reader cannot represent** (an exponent beyond any Decimal,
  an integer of 5,000 digits) rejects the whole file here; the other branch
  quarantined that one record and published the rest.
- **An adapter's integer-valued `Decimal('1200')` digests as the float
  1200.0** here, not as the JSON reader's int `1200`. An event first read
  from JSON and later re-sent by a custom adapter as such a Decimal, under
  the same identity and version, is not recognised as an exact replay.
  Decimals with a fraction, and every JSON-read value, digest as before.
- **Log lines carry event IDs, never arguments.** A startup refusal keeps
  its reason and an error keeps a known code, but a planner failure's code
  (`invalid_plan`, `bound_violated`, ...) is only in the audit row, not the
  log line.
